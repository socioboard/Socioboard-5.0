# Module: platform (shared infrastructure)

**Phase:** 0 (all parts), extended as later phases need · **Path:** `packages/core/src/platform/*` · **Depends on:** nothing inside Socioboard (lowest layer)

## Purpose
The shared building blocks every feature module uses. No business logic lives here. Feature modules receive these through their `createXModule(deps)` factory.

## Rules
- Nothing in `platform` imports from `modules`.
- Every external client (DB, Valkey, S3, SMTP) is created once at startup and injected, never imported as a global.
- Graceful shutdown (SIGTERM/SIGINT): the api turns readiness 503, stops accepting connections, lets in-flight requests finish (25 s) and closes keep-alive connections as they go idle; the worker lets active jobs finish (30 s); then connections close. A crash (uncaught exception or unhandled rejection) is logged as one fatal line and exits without a graceful shutdown, since the state is unknown. Jobs still running after 30 s are left to BullMQ, which retries them on another worker once their lock expires.
- Workspace isolation has two layers: `db.forWorkspace(id)` scopes every top-level query (reads, updates, deletes, creates; unknown operations fail closed), and relations between workspace-owned tables use **composite foreign keys** `(xId, workspaceId) → (id, workspaceId)` (with `@@unique([id, workspaceId])` on the target), so Postgres rejects a row in one workspace pointing at a row in another. Both were verified against Postgres on 2026-09-24: without the composite key, a nested `connect` linked another workspace's row. The scoped client also refuses nested relation writes (`connect`, `create`, … inside `data`): connecting a composite-key relation copies the target's `workspaceId` onto the row, which would move it to another workspace without any key violation (found by the P0-B9 harness). Set foreign key fields (`folderId`) instead.
- Email templates: `packages/emails` exports one async function per email (`verifyEmail({ name, url })` → `{ subject, html, text }`); senders add the recipient and call the mailer in the background. Locally every email lands in Mailpit (http://localhost:8025), which is the preview.
- Logs never contain secrets: any field named like a token, password, secret, API key, cookie or authorization header is redacted at any depth, including inside error objects.
